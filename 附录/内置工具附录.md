# 附录 A：NexAU 内置工具参考

> 本章参考官方文档 [Core Concepts: Tools](https://github.com/nex-agi/NexAU/blob/main/docs/core-concepts/tools.md) 与源码编写。

NexAU 为 Agent 提供了一套开箱即用的内置工具，涵盖文件操作、Shell 执行、Web 访问、会话管理，以及多智能体协作等场景。了解这些工具的完整用法有助于你为 Agent 搭配最合适的工具组合。

> 📦 **本章所有工具的官方 YAML 样例**均随教程附带，位于 [`附录/builtin-tools-samples/`](./builtin-tools-samples/)。每个工具小节都会标注对应 YAML 文件名——把这些 YAML 原样复制到你的 Agent 项目 `tools/` 目录即可直接使用。

## 目录结构

内置工具分为六类，位于 `nexau.archs.tool.builtin` 下：

```
builtin/
├── _sandbox_utils.py         # 沙箱工具共享底层
├── file_tools/               # 文件操作
│   ├── read_file.py        # 读取文本/图像/视频文件
│   ├── read_visual_file.py # 读取视觉文件（图像/视频帧）
│   ├── write_file.py       # 写入文件
│   ├── replace.py          # 定点替换文本
│   ├── apply_patch.py      # 应用补丁（Git Diff 格式）
│   ├── glob_tool.py        # 文件通配符匹配
│   ├── list_directory.py   # 列出目录内容
│   ├── read_many_files.py  # 批量读取多个文件
│   └── search_file_content.py  # 全文搜索
├── shell_tools/
│   └── run_shell_command.py    # 执行 Shell 命令
├── web_tools/
│   ├── google_web_search.py    # Web 搜索
│   └── web_fetch.py            # 抓取 URL 内容
├── session_tools/              # 会话管理
│   ├── write_todos.py         # 子任务列表
│   ├── ask_user.py            # 结构化提问
│   ├── complete_task.py       # 标记任务完成
│   └── save_memory.py         # 保存记忆
└── description/
    ├── agent_tool.yaml        # Agent（子代理）工具
    └── skill_tool.yaml        # LoadSkill 工具
```

## A.1 文件操作工具

### A.1.1 `read_file` — 读取文件

> 📄 **YAML 样例**：[`builtin-tools-samples/read_file.tool.yaml`](./builtin-tools-samples/read_file.tool.yaml)

读取文件内容，支持文本、图像、音频、视频等多种格式。

**参数说明：**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `file_path` | string | ✅ | 文件路径 |
| `offset` | number | ❌ | 文本文件的起始行号（0-based），用于分页 |
| `limit` | number | ❌ | 最大读取行数（文本文件分页用） |

**支持的格式：**
- 文本：`.md`、`.py`、`.yaml`、`.json` 等
- 图像：PNG、JPG、GIF、WEBP、SVG、BMP
- 音频：MP3、WAV、AIFF、AAC、OGG、FLAC
- 视频：MP4、AVI、MOV、MKV、WEBM、FLV、WMV、M4V（提取关键帧）

**注意：** 对于图像和视频文件，推荐使用 `read_visual_file` 以获得更好的视觉处理效果。

---

### A.1.2 `read_visual_file` — 读取视觉文件

> 📄 **YAML 样例**：[`builtin-tools-samples/read_visual_file.tool.yaml`](./builtin-tools-samples/read_visual_file.tool.yaml)

专门为多模态 LLM 设计的文件读取工具。图像直接返回 base64 数据，视频通过 `ffmpeg` 提取关键帧。

**支持的格式：** PNG、JPG、JPEG、GIF、BMP、WEBP、TIFF、SVG、MP4、AVI、MOV、MKV、WEBM、FLV、WMV、M4V

**视频帧提取设置（系统默认）：**
- 每 5 秒提取一帧
- 最多返回 10 帧

---

### A.1.3 `write_file` — 写入文件

> 📄 **YAML 样例**：[`builtin-tools-samples/write_file.tool.yaml`](./builtin-tools-samples/write_file.tool.yaml)

创建新文件或完全覆盖已有文件的全部内容。

**参数说明：**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `file_path` | string | ✅ | 文件路径 |
| `content` | string | ✅ | 要写入的内容 |

**行为：**
- 自动创建不存在的父目录
- 已存在的文件将被完全覆盖
- 适用于创建新文件或整文件替换

---

### A.1.4 `replace` — 精确替换文本

> 📄 **YAML 样例**：[`builtin-tools-samples/replace.tool.yaml`](./builtin-tools-samples/replace.tool.yaml)

对文件中已有文本做精确替换。要求提供被替换文本的完整上下文，确保只命中一次。

**参数说明：**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `file_path` | string | ✅ | 文件路径 |
| `old_string` | string | ✅ | 要替换的原始文本，需包含上下文确保唯一匹配 |
| `new_string` | string | ✅ | 替换后的新文本 |
| `instruction` | string | ✅ | 语义化说明（帮助定位变更意图） |
| `expected_replacements` | number | ❌ | 期望的替换次数，默认 1 |

**使用建议：**
- `old_string` 必须包含替换位置**前后至少 3 行的上下文**，以保证精确匹配
- 复杂修改应拆成多次小的 `replace` 调用
- 仅在需要整文件替换时才使用 `write_file`

---

### A.1.5 `apply_patch` — 应用补丁

> 📄 **YAML 样例**：[`builtin-tools-samples/apply_patch.tool.yaml`](./builtin-tools-samples/apply_patch.tool.yaml)

基于 Git Diff 格式的补丁应用工具。支持一次操作中新增文件、删除文件、移动文件和修改文件内容。

**参数说明：**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `patch` | string | ✅ | Git Diff 格式的补丁内容 |
| `dry_run` | boolean | ❌ | 是否仅预览（默认 false） |

**支持的补丁指令：**
- `*** Add File: <path>` — 新增文件
- `*** Delete File: <path>` — 删除文件
- `*** Update File: <path> >>> *** Move to: <new_path>` — 移动文件
- 标准 `@@` 格式的 diff 块

---

### A.1.6 `list_directory` — 列出目录

> 📄 **YAML 样例**：[`builtin-tools-samples/list_directory.tool.yaml`](./builtin-tools-samples/list_directory.tool.yaml)　·　配套：[`Glob.tool.yaml`](./builtin-tools-samples/Glob.tool.yaml)（通配符匹配）

列出目录下的文件和子目录，目录优先显示。

**参数说明：**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `dir_path` | string | ✅ | 要列出的目录路径 |
| `ignore` | string[] | ❌ | 忽略的 glob 模式列表 |
| `file_filtering_options` | object | ❌ | `.gitignore`/`.geminiignore` 过滤选项 |
| `show_hidden` | boolean | ❌ | 是否显示隐藏文件（默认 true） |

---

### A.1.7 `search_file_content` — 内容搜索

> 📄 **YAML 样例**：[`builtin-tools-samples/search_file_content.tool.yaml`](./builtin-tools-samples/search_file_content.tool.yaml)

在工作区内的文件中搜索匹配指定正则表达式的文本。

**参数说明：**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `pattern` | string | ✅ | 正则表达式模式（如 `function\\s+myFunction`） |
| `dir_path` | string | ❌ | 搜索目录（默认当前工作目录） |
| `include` | string | ❌ | 文件过滤模式（如 `*.js`、`*.{ts,tsx}`） |

---

### A.1.8 `read_many_files` — 批量读取文件

> 📄 **YAML 样例**：[`builtin-tools-samples/read_many_files.tool.yaml`](./builtin-tools-samples/read_many_files.tool.yaml)

按 glob 模式批量读取多个文件内容，文本文件拼接为一个字符串，图像/音频/PDF 返回内联数据。

**参数说明：**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `include` | string[] | ✅ | 包含的 glob 模式或路径列表 |
| `exclude` | string[] | ❌ | 排除的 glob 模式列表 |
| `recursive` | boolean | ❌ | 是否递归搜索（默认 true） |
| `use_default_excludes` | boolean | ❌ | 是否使用默认排除规则 |

**适用场景：** 快速了解项目结构、批量阅读配置文件、代码审查时批量拉取改动。

## A.2 Shell 工具

### A.2.1 `run_shell_command` — 执行命令

> 📄 **YAML 样例**：[`builtin-tools-samples/run_shell_command.tool.yaml`](./builtin-tools-samples/run_shell_command.tool.yaml)（异步流式）　·　[`run_shell_command_sync.tool.yaml`](./builtin-tools-samples/run_shell_command_sync.tool.yaml)（同步版本）　·　[`BackgroundTaskManage.tool.yaml`](./builtin-tools-samples/BackgroundTaskManage.tool.yaml)（后台任务管理）

执行 Shell 命令并返回输出。

**参数说明：**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `command` | string | ✅ | 要执行的命令 |
| `description` | string | ❌ | 命令的人话描述 |
| `dir_path` | string | ❌ | 运行目录（不填则使用项目根目录） |
| `is_background` | boolean | ❌ | 是否后台运行 |
| `timeout_ms` | number | ❌ | 超时时间（毫秒），0 表示不超时 |

**返回值包括：**
- `content` — stdout/stderr 合并输出
- `Exit Code` — 仅失败时返回
- `Background PIDs` — 仅后台任务时返回

**安全提示：**
- 限制 Agent 对 Shell 命令的权限范围
- 从沙箱而非生产环境执行高风险操作
- 修改文件、进程或系统状态的命令需严格控制

## A.4 会话管理工具

### A.4.1 `write_todos` — 子任务列表

> 📄 **YAML 样例**：[`builtin-tools-samples/write_todos.tool.yaml`](./builtin-tools-samples/write_todos.tool.yaml)

管理多步骤任务的子任务列表，帮助 Agent 跟踪执行进度。

**任务状态定义：**
- `pending` — 尚未开始
- `in_progress` — 进行中（同一时间只能有一个）
- `completed` — 已完成
- `cancelled` — 已取消

**使用场景：** 复杂查询需要多步执行时，用 `write_todos` 建立任务清单，逐步推进。

---

### A.4.2 `ask_user` — 结构化提问

> 📄 **YAML 样例**：[`builtin-tools-samples/ask_user.tool.yaml`](./builtin-tools-samples/ask_user.tool.yaml)

向用户提出一个或多个结构化问题。前端渲染问题 UI 后，用户回答以常规消息返回。

**问题类型：**
- `choice` — 选择题（提供 2-4 个选项）
- `text` — 文本输入题
- `yesno` — 是非题

**次数限制：** 最多 4 个问题。

### A.4.3 `complete_task` — 标记任务完成

> 📄 **YAML 样例**：[`builtin-tools-samples/complete_task.tool.yaml`](./builtin-tools-samples/complete_task.tool.yaml)

当 Agent 已完成其分配的任务时调用，通知系统任务结束。

## A.5 Agent 工具（子代理）

### A.5.1 `Agent` — 委派子代理

> 📄 **YAML 样例**：[`builtin-tools-samples/agent_tool.yaml`](./builtin-tools-samples/agent_tool.yaml)（官方描述模板）

将任务委派给子代理并行执行。支持创建新子代理和恢复已完成的子代理。

**参数说明：**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `sub_agent_name` | string | ✅ | 子代理名称（必须在配置中注册） |
| `message` | string | ✅ | 委派消息/指令 |
| `sub_agent_id` | string | ❌ | 恢复已完成的子代理 ID |

**使用建议：**
- `explore` 类型子代理适合只读调查任务，安全无副作用
- `worker` 类型子代理可执行写入操作，但需要避免文件冲突
- 对独立且可并行的任务使用子代理可显著加速过程

## A.7 在 Agent 中注册内置工具

在 `agent.yaml` 的 `tools:` 列表中声明需要使用的工具，每个条目绑定一个官方提供的 tool YAML：

```yaml
tools:
  - name: web_search
    yaml_path: ./tools/WebSearch.tool.yaml
    binding: nexau.archs.tool.builtin.web_tools:google_web_search
  - name: read_file
    yaml_path: ./tools/read_file.tool.yaml
    binding: nexau.archs.tool.builtin.file_tools:read_file
```

**步骤**：

1. 从 [`附录/builtin-tools-samples/`](./builtin-tools-samples/) 复制需要的 `*.tool.yaml` 到你的项目 `tools/` 目录
2. 在 `agent.yaml` 的 `tools:` 下用 `yaml_path` 引用这些文件
3. 用 `binding` 指定绑定的内置实现（见每个工具小节的「YAML 样例」文件，其顶部注释给出了对应的 `binding` 路径）

## A.8 工具输出控制

### returnDisplay

工具返回字典时可包含 `returnDisplay` 字段，用于提供人话摘要（仅前端展示，不发送给 LLM）。

### 工具输出格式化器

通过 `formatter` 指定工具输出格式：

```yaml
type: tool
name: my_shell
formatter: xml  # 或其他自定义格式化器
```

内置 `xml` 格式：将结构化数据转为 XML 供 LLM 解析。自定义格式器通过导入路径指定：

```yaml
formatter: my_project.formatters:format_my_output
```

### 长输出截断

通过 `LongToolOutputMiddleware` 中间件截断超出阈值的长工具输出：

```yaml
middlewares:
  - import: nexau.archs.main_sub.execution.middleware.long_tool_output:LongToolOutputMiddleware
    params:
      max_output_chars: 10000
      head_lines: 50
      tail_lines: 30
      bypass_tool_names:
        - execute_bash  # 已在沙箱层截断
```

## A.9 外部工具（Caller-Executed）

外部工具由**调用端**而非 Agent 执行，NexAU 仅将工具 schema 注册给 LLM，实际执行交给调用端处理。

**声明方式（YAML）：**
```yaml
type: tool
name: read_file
kind: external   # 关键：不绑定 Python 实现
```

**典型场景：** IDE 插件执行、跨语言集成、安全隔离工具（如沙箱内的文件操作）。

详见 [RFC-0018](https://github.com/nex-agi/NexAU/blob/main/docs/rfcs/0018-external-tool.md)。
